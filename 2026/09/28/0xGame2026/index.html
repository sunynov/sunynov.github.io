这时候需要jwt伪造，经查询发现是CVE-2026-39999，一个存在于 Apache APISIX 中的 JWT 算法混淆

该漏洞的问题在于 APISIX 的 jwt-auth 插件盲目信任了 JWT Header 中声明的 alg 字段。当攻击者将 Header 中的 alg 篡改为对称加密算法（如 HS256） 时，服务端会错误地切换验证逻辑，直接使用配置的公钥（本应公开）作为 HMAC 的密钥 来验签

漏风的沙箱

源码很长，我们重点看AST沙箱这部分

也就是说一共三层WAF，第一层是正则过滤并且做了NFKC归一化处理不能用Unicode绕过；第二层是AST沙箱，对一些函数名方法名进行了检查，不能出现在黑名单中；第三层就是受限的沙箱，但是open、eval等危险方法仍然存在。

  • o = open 里的 open 是一个 ast.Name，不是 ast.Call，所以 visit_Call 不检查它；visit_Attribute 也管不到（它不是属性访问）。
  • o('/app/flag.txt') 是一个 ast.Call，但 func 是 ast.Name，id == 'o'，不在 BANNED_FUNCTIONS 里 → 放行。
